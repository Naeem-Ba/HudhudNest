# بوابة إصدار تغييرات UI وCapacitor

تنطبق هذه البوابة على أي إصدار يتضمن تغييرات في HTML أوSCSS أومكوّنات UI أوNavbar أوOverlays أوCapacitor أوإعدادات Android/iOS.

## قاعدة القرار

- **منع الدمج:** إذا لم تُوثق العروض 375/768/1440 للصفحات المتأثرة.
- **منع الإصدار:** إذا لم يُنفذ اختبار على جهاز فعلي واحد على الأقل بعد آخر تغيير UI/Capacitor.
- DevTools مفيد لفحص العرض، لكنه لا يثبت Safe Area أوkeyboard أوHardware Back أوsystem bars.

## قبل الدمج

- [ ] `npm install` أو `npm ci` نجح.
- [ ] `npm run typecheck` نجح.
- [ ] `npm run build:prod` نجح، أو وُثّق عائق بيئي خارجي بوضوح.
- [ ] الصفحات المتأثرة اختُبرت على 375px و768px و1440px.
- [ ] نُفذت دورة RTL ودورة LTR.
- [ ] لا يوجد horizontal overflow.
- [ ] أُرفقت أدلة للفشل والإصلاح عند وجود regression.

## قبل الإصدار — جهاز حقيقي إلزامي

### Android فعلي

- [ ] الموديل وإصدار Android موثقان.
- [ ] Navbar لا تدخل تحت Status Bar.
- [ ] Drawer وFilter Drawer لا يدخلان تحت system bars.
- [ ] Hardware Back يغلق أحدث Overlay أولاً.
- [ ] الرجوع من صفحة داخلية يعمل، والخروج يحدث فقط عند الجذر.
- [ ] فتح وإغلاق الكيبورد لا يخفي الحقل النشط أو يترك فراغاً دائماً.
- [ ] Portrait وLandscape اختُبرا للصفحات المتأثرة.

### iOS عند توفر منصة iOS

- [ ] جهاز ذو notch أوDynamic Island اختُبر.
- [ ] Navbar وDrawer يحترمان Safe Area وHome Indicator.
- [ ] حقول Login/Forms لا تسبب auto-zoom غير مرغوب.
- [ ] `100dvh` وسلوك الكيبورد اختُبرا فعلياً.

عدم وجود مشروع iOS لا يسمح بادعاء أن iOS اختُبر؛ سجّل الحالة كـ`Not available` مع تذكرة متابعة.

عند الفشل، سجّل:

1. المسار واللغة والعرض أو الجهاز.
2. خطوات إعادة المشكلة.
