# برومت: صفحة إعادة تعيين كلمة المرور تطلب «رمز الاستعادة» يدويًا

## الأعراض
بعد «نسيت كلمة المرور» يصل البريد، لكن الرابط يفتح `/auth/reset-password` بنموذج فيه
البريد + «رمز الاستعادة» + كلمة المرور، ولا يوجد حقل لتأكيد كلمة المرور.

## الجذر (مؤكَّد من الكود والوثائق)
- «رمز الاستعادة» = `token` الذي يولّده ASP.NET Identity وتضعه الخلفية في الرابط:
  `PasswordResetUrlBuilder` يبني `{Frontend:PasswordResetUrl}?email=..&token=..`.
  ليس له علاقة برمز الهاتف (OTP) — مسار الهاتف منفصل: `/auth/phone-password-reset`.
- `reset-password.page.ts` لا يقرأ `ActivatedRoute` إطلاقًا، فيطلب القيمتين يدويًا.
- النموذج يعرّف `confirmPassword` لكن القالب لا يعرضه؛ والزر معطّل لأن الحقل المخفي
  `required` فلا يصحّ النموذج أبدًا. وفي حالة عدم التطابق لا يُعاد `loading` إلى false.
- الخلفية (`ResetPasswordCommand`) تتحقق أصلًا من `NewPassword == ConfirmPassword` —
  لا تغيير مطلوب فيها ولا في العقد `POST /auth/reset-password`.

## المطلوب (الواجهة فقط — مستودع HudhudNest)
1. قراءة `email` و`token` من `queryParamMap` عند التحميل، وعدم عرضهما كحقول إدخال.
   يُعرض البريد نصًّا للقراءة فقط؛ التوكن لا يُعرض أبدًا ولا يُسجَّل.
2. حقلان فقط: «كلمة المرور الجديدة» و«تأكيد كلمة المرور الجديدة»، مع تحقق فوري
   من الطول (≥ 8) ومن التطابق (رسالة `AUTH.ERRORS.PASSWORD_MISMATCH`).
3. رابط ناقص/تالف (لا email أو لا token) → رسالة «الرابط غير صالح» + زر لطلب رابط جديد
   `/auth/forgot-password`، بدل نموذج يطلب رمزًا.
4. إعادة `loading` إلى false في كل مسار، وبعد النجاح رابط إلى تسجيل الدخول.
5. مفاتيح ترجمة جديدة في `ar/en/de` (التكافؤ مفروض بـ `tools/lib/i18n-keys`).
6. اختبارات وحدة: قراءة الوسائط (بما فيها توكن بـ `+ / =`)، رابط ناقص، عدم التطابق،
   وإرسال `{email, token, newPassword, confirmPassword}` كما هو.
7. تحديث الوثائق (`FRONTEND_BACKEND_CONTRACT.md` والمرجع) ثم PR إلى `main`.

## معايير القبول
- فتح الرابط من البريد يعرض حقلي كلمة المرور فقط.
- عدم التطابق يمنع الإرسال برسالة واضحة.
- `npm run typecheck`، الاختبارات، `audit:frontend`، فحص i18n — كلها خضراء.
